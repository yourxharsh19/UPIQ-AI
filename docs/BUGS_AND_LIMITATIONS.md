## Known limitations

- No backend budget persistence, investment service, fraud detector, push notifications, or production admin console.
- Budget forecast is frontend-derived prototype logic; browser-local budgets are not shared between devices.
- Voice input depends on browser speech APIs; compatibility and end-to-end behavior have not been verified here.
- Backend parses text-based PDF/CSV content; current frontend upload accepts PDF only and scanned-image OCR is not implemented.
- Financial chat supports a bounded intent set and requires configured/running Ollama for System C generation. Unsupported questions and service errors are not equivalent to general-purpose financial advice.
- Report PDF endpoint is present, but frontend archive/preview workflow is not a persisted report-history implementation.
- Transaction/calculation data has no backend currency field; display currency selection must not be confused with stored currency provenance.
- Research A/B/C runner records generation output and metadata only. There are no answer-quality metrics, statistical analysis, or findings supporting a system superiority claim. Local recorded System B runtime issues require bounded reproduction.
- Backend schema uses Hibernate `ddl-auto: update`; no production migration workflow is evidenced by the current configuration.

## Verification note

Entries above are based on source and documentation inspection, not a fresh backend/frontend test run or production deployment. Fixed items reflect reviewed implementation and prior focused tests where noted; they are not claims of end-to-end runtime verification.
